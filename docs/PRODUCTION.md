# Standalone production release boundary

This branch runs community governance and a separate append-only register of staff-recorded external payments. It performs no real money or blockchain transfers. Existing financial simulations stay explicitly labelled and unchanged. See [standalone product and deployment guidance](STANDALONE.md).

Use an exact HTTPS APP_ORIGIN, production NODE_ENV, ALLOW_DEMO_SEED=false and FUNDICATE_MODE=standalone. Keep PostgreSQL private with verified TLS or an explicitly isolated internal network. RUNTIME_DATABASE_URL is used by Compose web/maintenance; DATABASE_URL and POSTGRES_PASSWORD are operator-only migration/provisioning credentials, never passed into those runtime containers. The fixed runtime role has DML privileges, no schema ownership/superuser rights and read-only migration metadata. Bootstrap generates separate passwords and extends older ignored deployment configuration without replacing existing credentials or data.

Configure TRUSTED_CLIENT_IP_HEADER to x-real-ip or cf-connecting-ip only when a trusted proxy overwrites it and blocks direct application access. Public production authentication fails closed without this policy. Proxy timeouts, body limits and edge rate controls must complement database-backed account/IP quotas. Preserve the full 250000-byte pairwise ballot request size. Cookies are HTTP-only, same-site and secure on HTTPS; sensitive authority/payment-record actions require recent reauthentication.

Monitor readiness, safe structured error categories/request IDs, job failures and accounting checks. Use additive migrations and operator backups. Test restores in isolated databases before switching traffic. A code rollback never authorizes deletion or rewriting of posted records. Review multi-replica pool sizes/shared quotas, jobs and caching before horizontal scaling.

The final handoff and workflow receipts establish tested source scope. Actual local container OS/dependency scans and their retained database findings are recorded in the [dated container audit](security/container-audit.md); these scans do not certify the image or a hosted environment. No cloud/hosted deployment, external security certification or penetration test is implied. Email verification, self-service account recovery and MFA remain onboarding limitations. TLS/proxy policies, secret custody and hosted backup/monitoring must be verified in the actual target environment before broad public launch. Mainnet and automated real-money processing are outside this branch.
